# MSM Production Release Checklist

## 1. Source and version

- [ ] Release version is updated consistently in the application and Agent manifests.
- [ ] `Cargo.lock` is regenerated by Cargo after dependency changes and committed.
- [ ] `bun.lock` is current.
- [ ] No secrets, certificates, private keys, or local credentials are committed.
- [ ] Release notes describe protocol, installer, and migration changes.

## 2. CI gates

- [ ] Frontend CI: `bun install --frozen-lockfile` succeeds.
- [ ] Frontend CI: `bun run build` succeeds.
- [ ] Rust CI: `cargo check --workspace` succeeds.
- [ ] Rust CI: `cargo test --workspace` succeeds.
- [ ] Windows CI: `cargo build --release -p msm-agent` succeeds.
- [ ] Windows CI: application installer build succeeds.
- [ ] Windows CI: Agent packaging script succeeds.
- [ ] No required CI check is skipped or allowed to fail.

## 3. Security

- [ ] Agent service runs only with TLS certificate and key configured.
- [ ] Viewer uses `wss://` for production endpoints.
- [ ] Certificate SAN matches the Agent hostname used by the Viewer.
- [ ] Private key is ACL-restricted to LocalSystem/Administrators.
- [ ] Agent token is DPAPI-protected.
- [ ] Legacy plaintext token migration has been tested.
- [ ] VNC password is independent from the Agent token.
- [ ] VNC ticket is short-lived and session-bound.
- [ ] Direct worker/VNC ports are inaccessible from the network.
- [ ] Authentication failures return 401 and do not disclose credentials.
- [ ] Logs do not contain Agent tokens, VNC passwords, or private keys.

## 4. Windows service

- [ ] Fresh installation succeeds on a clean Windows machine.
- [ ] Upgrade succeeds while workers are active.
- [ ] Service reaches `Running` after installation.
- [ ] Service starts automatically after reboot.
- [ ] Service recovery restarts the Agent after process failure.
- [ ] Service stop terminates workers.
- [ ] Service uninstall removes the SCM entry after DELETE_PENDING convergence.
- [ ] Reinstall does not leave stale worker processes or listeners.

## 5. Session/worker lifecycle

- [ ] One worker is created per eligible interactive session.
- [ ] Duplicate concurrent `StartSession` requests never create duplicate workers.
- [ ] Worker crash causes recovery.
- [ ] Repeated worker failure backs off instead of spawning continuously.
- [ ] Session disappearance terminates its worker.
- [ ] Worker port exhaustion returns a controlled error.
- [ ] Worker binds only to loopback.
- [ ] Multiple users/sessions work simultaneously.
- [ ] Lock/unlock and disconnect/reconnect behavior is validated.
- [ ] Monitor hotplug/resolution changes do not permanently kill capture.

## 6. Viewer

- [ ] Multiple Agents can be connected simultaneously.
- [ ] Agent reconnect works after a temporary network outage.
- [ ] Manual Viewer disconnect remains intentional and does not auto-reconnect.
- [ ] Agent removal clears its saved credential.
- [ ] 401/timeout/TLS/protocol errors have useful user-facing messages.
- [ ] Remote mouse input works.
- [ ] Remote keyboard input works, including modifiers and function keys.
- [ ] View-only mode is enforced.
- [ ] Fullscreen controls do not intercept remote edge interactions.
- [ ] VNC disconnect cleans up the Viewer state.

## 7. Clipboard

- [ ] Windows-to-Viewer text clipboard works.
- [ ] Viewer-to-Windows text clipboard works.
- [ ] Unicode text is preserved.
- [ ] Clipboard feedback loops are impossible.
- [ ] Large clipboard payloads are bounded or rejected safely.
- [ ] Clipboard failures do not kill the worker.
- [ ] Locked/disconnected sessions are handled cleanly.

## 8. Packaging

- [ ] NSIS installer installs and uninstalls cleanly.
- [ ] MSI installer installs and uninstalls cleanly.
- [ ] Agent package contains both release binaries and the installer script.
- [ ] Installer version matches Agent version.
- [ ] TLS certificate/private key are supplied out-of-band and never bundled by default.
- [ ] Upgrade preserves existing TLS assets when no replacement is supplied.
- [ ] Uninstall removes binaries and service state without deleting externally managed TLS assets unexpectedly.

## 9. Observability

- [ ] Agent startup/shutdown is logged.
- [ ] Worker PID/session lifecycle is logged.
- [ ] Worker crash/retry/backoff is logged.
- [ ] Authentication failures are logged without credentials.
- [ ] Logs rotate or are bounded by the deployment sink.
- [ ] Operators can retrieve logs from a failed endpoint.

## 10. Release candidate soak test

Run the release candidate continuously for at least 24 hours on a representative Windows host with multiple interactive sessions.

- [ ] Reboot recovery passed.
- [ ] User login/logout passed.
- [ ] Session disconnect/reconnect passed.
- [ ] Worker crash recovery passed.
- [ ] Network outage/recovery passed.
- [ ] Viewer restart/recovery passed.
- [ ] No unbounded process growth.
- [ ] No memory/resource leak observed.
- [ ] No credential leakage observed.

## 11. Final sign-off

- [ ] All P0/P1 findings are closed.
- [ ] CI is green for the exact release commit.
- [ ] Windows installers have been tested on a clean machine.
- [ ] Release artifacts are checksummed and archived.
- [ ] Windows binaries are code-signed.
- [ ] Release notes and upgrade instructions are published.
- [ ] Rollback artifact is available.
- [ ] Production deployment owner has approved the release.
